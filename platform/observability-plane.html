EIL · observability plane

The map's stage 07, opened up. Every agent action becomes a canonical event; events become spans; spans become the four numbers an executive reads. The rule underneath all of it: a number that cannot be measured is reported as unknown, never as zero.

↗ system map ↗ cockpit

01Captureone contract, every producer

One canonicalEventSchema for every producer — Copilot, Amp, MaaS, the harness, the egress proxy and EIL. Strict: an unknown field is a rejection, not a warning.

identityprincipal, actor type, team
tracerun / trace / span / parent span
workflowworkflow, attempt, step, stage, layer, role
capturemetadata_only or approved_content, with policy version
usageinput / output / cache tokens, provider-reported cost

Capture mode is enforced by the schema, not by convention: metadata_only with contentIncluded: true is refused at validation.

A retrieval records a sha256 digest of the query and never the query. Verified by injecting a raw query into an emitted event and asserting the store rejects it.

An idempotencyKey makes a retry a no-op; a revisionDigest makes a correction a new row rather than an overwrite. Nothing is ever mutated in place, so the ledger can be replayed.

02Measurederived, never asserted

A span is measured from its own started and terminal observation — not from the gap between consecutive steps, which also contains queue time, CI scheduling and human review.

An incomplete pair returns known: false with a reason: no_terminal_observation, no_started_observation, terminal_precedes_started. Never 0. An in-flight or crashed span must not render as the fastest step on the page.

Work is the sum of measured spans. Wait is elapsed minus work. On the reference run that split is 32% active, 68% waiting — which turns an AI-spend conversation into a throughput conversation.

one unmeasurable spanmakes the whole work total unknown — summing only the measurable ones understates work, and understated work overstates wait
overlapping spansreport work_exceeds_elapsed, not a negative wait bar

Provider-reported cost is persisted as given. Internal cost is calculated from a versioned price book, and the version active at request time is stored with it — history is never re-priced at today's rates.

Provenance is carried, not flattened: reported, estimated, or unknown. A missing price shows unknown, never $0.

03Attributeproven, or it does not say so

Every step carries a role — inception · activity · evidence · artifact · verification · outcome — and links carry a relation, a confidence and its evidence.

The vocabulary is portable on purpose: layer is ticketing and ci, not Jira and Bamboo, so swapping the corporate system is a connector rather than a redesign.

A deterministic link must have confidence 1. An evidence link is forbidden from claiming it, and a calibrated one must carry measured precision and sample size.

So the page can say "76% deterministic, 24% inferred at precision 0.9." Competing AI-ROI dashboards state numbers without a confidence; this one cannot.

A trace is not complete because it has steps. It is complete when it has an inception, an artifact, a verification and an outcome, with a causal path between them.

unverified_artifactnothing verified what was produced
outcome_without_verificationit shipped, unproven
causal_cycle · dangling_link · unrooted_stepthe graph does not hold

Break one link and verified shipping reads Unproven instead of Proven.

04Presentsame trace, three surfaces

Executive view and developer ledger from one trace. Positioned waterfall, evidence per span, and an unavoidable SIMULATED DATA label wherever a corporate system is a fixture.

The same numbers with no browser and no port. Active and wait are different glyphs, not different colours, so the split survives a washed-out projector and a screenshot in a deck.

Runs the real products rather than narrating them, and closes with a ledger counting what actually ran. A skipped act is named under not proven this run — never narrated as if it passed.

06Feedbackthe loop back to 02 ingest

Every retrieval writes an audit row: who asked, what matched, how many results — never the result content. Aggregated, that is the signal for what to index next and what to stop indexing.

This is the arrow that leaves the observability node on the system map and returns to 02 Ingest and 03 Index.
